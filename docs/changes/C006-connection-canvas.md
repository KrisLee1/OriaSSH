# 连接画布、主机服务与 SSH 登录身份方案

2026-11-24 · 第二、三阶段已实施。本文记录新版交互、数据迁移和验收要求。已发布能力见[项目状态](../PROJECT_STATUS.md)，既有组件和平台约定见[界面开发规范](../ui-development.md)。

首批实现包含主机外观、画布添加主机、服务分组与配置入口、旧转发的首个登录身份绑定和系统密码迁移。第二阶段已实现三种建线手势、L/D 自动端口、双端浮卡及运行路径与待生效路径展示。第三阶段已接入端口变量、执行身份选择、主机日志、查找及批量操作，并完成导航切换。普通终端、SFTP、逐跳身份和身份删除替换仍属于第一阶段的待办。[实施记录](../PROJECT_STATUS.md#c006-第三阶段--命令日志与导航)

## 1. 从一台主机开始

用户在画布上创建 SSH 主机卡片，在卡片里添加服务，再把「此电脑」与目标服务连起来。画布承担主机、服务和转发的日常管理。日志从所属主机进入。顶部撤下转发、服务、主机和日志四个独立列表页签，保留终端、文件和设置入口。

| 位置 | 常驻信息 | 主要操作 |
| --- | --- | --- |
| 画布工具 | 添加主机、查找、适应视口 | 按主机、服务名或端口定位并高亮，选中多条线或对全部转发批量启停 |
| 此电脑卡片 | 每条线在本机一端的地址、端口和用途 | 建立转发、点击端口修改、复制实际监听地址 |
| SSH 主机标题 | 图标、颜色、主机名、SSH 地址和端口 | 管理登录身份、打开主机日志，更多菜单提供主机详情、编辑、测试与删除 |
| 主机卡片正文 | 每个服务沿用现有转发卡片的样式，显示名称、图标、目标地址和服务端口 | 添加服务、编辑服务、运行服务命令、从连接点建线 |
| 转发连线 | 方向、L/R/D 类型和运行状态 | 从两端查看同一条转发，启动或停止、查看详情、编辑、删除 |

首次进入只显示「此电脑」。点击「添加主机」或画布空白处的右键菜单，可手动填写主机或选取已发现的 SSH 配置，并选择图标和颜色。外观写入应用配置；配置发现仅解析文件。保存后将卡片放在创建位置或视口内的空闲位置，卡内直接提供「添加服务」。只有用户选择测试或启动连接时才发起相应 SSH 操作。

添加服务支持新建、使用模板或选取已有服务。只有端口的服务即可连线。只有命令的服务也可保存和执行动作，建线时提示先设置端口。共享服务显示在各关联主机卡内，编辑前显示影响范围。服务区提供服务命令，连线提供转发操作，两者分别显示运行状态。

## 2. 三种转发的端点与建线手势

下表以「此电脑」在左、SSH 主机在右为例。箭头表示从监听入口到目标或代理出口；数据可以双向流动。拖动卡片只改变画布位置。

| 用户目的 | 此电脑端点 | 连线 | SSH 主机端点 |
| --- | --- | :---: | --- |
| L · 从本机访问远端服务 | 本机监听，如 `127.0.0.1:51842` | L → | 具体服务，如 PostgreSQL · `db.internal:5432`，由 SSH 主机访问 |
| R · 让远端访问本机可达的服务 | 本机目标，如 `127.0.0.1:3000` | ← R | 远端监听，如 `127.0.0.1:8080` |
| D · 通过 SSH 主机使用动态代理 | 本机 SOCKS5 监听，如 `127.0.0.1:51843` | D → | 主机专用「SOCKS5 出口」，目的地址由客户端逐次指定 |

- **L** 从「此电脑 → 建立转发」拖到服务卡的连接点。确认卡展示本机监听、SSH 主机与最终服务地址。服务可以位于 SSH 主机自身，也可以位于该主机可达的其他地址。
- **R** 从「SSH 主机 → 添加 → 远程监听」拖到此电脑，选择或填写本机可达的目标。远端监听地址和端口在 SSH 主机卡编辑，本地目标在此电脑卡编辑，填写应用实际使用的端口。远端默认绑定回环地址并标注「仅远端主机本机可访问」；选择其他绑定地址时显示服务端策略与防火墙的可达性说明。已有绑定服务的 R 规则继续以服务端口设置远端监听。
- **D** 从「此电脑 → 建立 SOCKS5 代理」拖到 SSH 主机的代理出口，选定登录身份即可。监听地址沿用本机回环限制。同一 D 规则关联的多个服务在浮卡中作为「通过代理打开」的快捷入口，共用一条线。

建线过程中只高亮兼容端点。没有拖动设备时，可先点击起点、再点击终点；键盘可聚焦起点并选择终点。落点确定后显示路径、登录身份与端口，提供「保存」和「保存并启动」。Esc 或拖到空白处取消。未使用的新增端点在建线时显现；文件传输沿用独立的连接点和连线。

## 3. 本机端口与双端操作卡

L 和 D 新转发的本机监听默认选「自动」。Rust 在启动时让操作系统分配可用端口，并从实际监听器回报地址。未启动时显示「自动」，监听成功后显示可复制的地址。下次启动可能分到其他端口；需要稳定地址的用户可点击此电脑卡上的端口数字，切换到「固定端口」。打开服务、VNC 和代理浏览器等入口使用本次运行的实际地址。R 的本地目标端口始终取自用户指定的应用。

端口数字和旁边的连接点有独立点击区域。运行中修改网络参数时提供「保存，下次启动生效」与「重启并应用」。前者同时标出当前运行值与待生效值；后者说明会中断这条连接。固定端口占用或远端拒绝监听时，在对应端点显示失败原因和编辑入口。监听、重连、失败、停止与流量均由 Rust 快照或事件驱动。

悬停或聚焦任一端点时，同时高亮整条线和对端。交互式浮卡显示完整路径、登录身份、运行状态，以及「启动／停止转发」「详情」「编辑」「删除」。指针可从端点移入浮卡操作；点击或按 Enter 固定浮卡，Esc 关闭并恢复焦点。状态同时使用文字和图形。服务卡为每条已有转发保留独立连接点，支持同一服务映射到多个本机端口。停止或删除其中一条，仅作用于所选规则；删除操作衔接现有撤销入口。

## 4. 服务端口变量

服务编辑器提供「插入变量 → 服务端口」，写入 `{{service.port}}`，支持脚本文本和结构化参数值。例如，JupyterLab 服务端口为 `8888`，命令草稿为 `jupyter lab --port={{service.port}}`，执行预览为 `jupyter lab --port=8888`。即使此电脑一端分到 `51842`，命令仍使用 `8888`。

Rust 使用同一服务版本生成预览与执行内容，变量只展开为 1–65535 的端口数字。若引用变量但缺少有效端口，定位到端口字段；预览后配置被修改，则刷新预览再执行。编辑服务端口时列出受影响的转发，活动连接显示其实际运行路径直至重启。旧命令保留原文和执行语义，用户显式插入变量后启用替换。命令继续遵循既有执行许可和确认流程。

## 5. 一张主机卡上的多个登录身份

主机保存名称、外观、SSH 地址、端口和路由。登录身份有独立 ID，保存显示名、SSH 用户名、认证方式与必要的密钥文件引用。标题显示「开发机 · lab.example:22」，旁边是「登录身份 2」和「日志」。例如，同一张卡可以配置「日常开发 · alice · SSH Agent」和「部署 · deploy · 指定私钥」。

| 操作 | 交互与生效范围 |
| --- | --- |
| 添加和管理 | 创建主机时可添加首个身份。点击「登录身份」可添加、编辑、测试、设为默认或删除。支持自动、密码、私钥文件与 SSH Agent 认证 |
| 管理已存密码 | 管理面板显示该身份的密码保存状态，提供更换和清除。选择记住密码后，由 Rust 在 SSH 密码认证成功时写入系统凭据库。配置和导出仅携带非秘密字段，私钥口令按需输入 |
| 新建或重连转发 | 单一身份自动选用，多身份在建线确认卡预选默认值。保存时绑定具体身份 ID。启动、自动重连和后台恢复沿用该绑定。修改默认值只影响后续新建连接 |
| 执行服务命令 | 确认区明确显示执行主机和用户名，可为服务在该执行主机上记住身份。例如 alice 建立隧道，deploy 管理服务进程 |
| 打开终端和文件 | 终端与 SFTP 使用同一身份选择器。会话、服务终端、后台任务及恢复记录区分实际用户；跳板按每一跳指定的身份认证 |
| 删除身份 | 列出引用的转发、服务命令和活动会话。用户可指定替代身份并预览变更；需要停止或重连的会话单独确认，取消时保留原绑定 |

当前系统密码条目按主机 ID 定位，并校验地址、端口、用户名和认证方式。新版须以具体身份隔离凭据，并保留连接信息校验；清除 alice 的密码只作用于 alice。主机指纹仍按实际 SSH 端点核验。现有实现见[主机与运行模型](../../src/types.ts)及[系统凭据存储](../../src-tauri/src/credentials.rs)。

## 6. 主机日志与历史活动

点击主机卡的「日志」打开该主机的时间线，展示连接测试、转发启停、认证与连接错误，可按身份、服务、转发或异常筛选。从连线详情点击「查看日志」时，时间线预选这条转发。此电脑的「历史活动」提供无法可靠归属的旧记录入口。

新事件保存稳定的主机、规则与身份引用，并记录发生时的用户名；有明确服务关联时记录服务引用。这样即使后来删除线或更改名称，历史仍能回到原主机和用户。沿用日志白名单，密码、私钥正文、口令与命令输出均排除在活动日志之外。[当前活动归属逻辑](../../src/features/tunnels/activity-model.ts)

## 7. 旧配置迁移

| 既有数据 | 升级结果 |
| --- | --- |
| 主机与 SSH 别名 | 保留 ID、手动位置、视口、来源与路由。每个旧主机的用户和认证设置生成一个默认身份，原引用绑定到它。地址相同的别名保留各自的路由和来源 |
| 系统凭据 | 在旧绑定校验通过后，将密码条目关联至该主机迁出的默认身份。替换成功后再清理旧条目；失败可重试，避免误清其他用户或把密码写入配置备份 |
| L/R/D 规则 | 保留规则 ID、名称、固定端口、方向、目标与启动偏好。已关联服务的 L 落在其服务卡，R 落在远端监听口，D 落在主机代理出口 |
| 未绑定服务的旧 L | 按原目标地址与端口呈现服务卡，保留原规则及原名。再次加载或重复迁移时复用同一映射 |
| 共享、未分配的服务 | 共享服务保留稳定 ID 和各主机关联；未分配的服务可在「添加服务 → 已有服务」中找到。导入时重映射主机、身份和服务引用，沿用原有命令执行许可保护 |
| 旧日志与旧命令 | 可可靠解析的事件归入对应主机，其余进入历史活动。保留旧命令文本、版本和许可 |

配置迁移需可重复执行，并保留迁移前的配置备份。先验证旧数据在新画布上的映射和既有操作入口，再撤下四个旧页签。

## 8. 实施顺序与验收

1. **主机、身份与服务卡。** 完成配置迁移、身份隔离、主机外观和服务卡投影。覆盖空主机、多服务、共享服务、同地址不同跳板、已存凭据及重复迁移。
2. **连线与端口。** 完成 L/R/D 建线、自动端口、双端浮卡、运行态和相关打开入口。用隔离回环 SSH 验证三个方向、停止释放端口、端口占用、远端拒绝监听，以及两条线连接同一服务时能独立启停。
3. **命令、日志与导航。** 接入服务端口变量和身份选择，核对执行预览、缺端口提示、历史归属、查找和批量操作。核对主机发现、模板、导入导出和删除撤销均有可达入口后切换导航。

端到端验收使用同一张测试主机卡和两个隔离账号。由 alice 同时运行 L 和 D，deploy 运行 R 并执行带服务端口变量的命令。分别检查线的箭头、两端地址、实际执行用户与日志；切换默认身份、单独停止一条线、重启应用后，逐条核对身份绑定、端口策略和恢复行为。整个流程还需在最小窗口中通过键盘完成，覆盖深浅主题、减少动态效果、弹层焦点返回及长名称显示。网络验证仅使用独立本地夹具。
